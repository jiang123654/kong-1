# Skill 03：内容生成与模块设计

> 所属技能：计划物流领域PPT内容生成专家
> 版本：v1.0
> 功能：基于大纲逐页生成PPT内容，设计分模块布局和丰富描述

---

## 一、功能定位

Skill 03是PPT生成的**第三阶段**，负责基于大纲逐页生成详细的PPT内容，包括标题、副标题、正文要点、数据标注、逻辑推导和审计合规检查。

---

## 二、内容生成流程

```mermaid
graph LR
    A[PPT大纲] --> B[逐页循环]
    B --> C[页面类型识别]
    C --> D[模块设计]
    D --> E[内容填充]
    E --> F[审计合规检查]
    F --> G[输出逐页内容]
```

## 四、内容丰富度提升规则

### 4.1 正文要点编写规范

每页正文要点**不少于3条，不超过5条**，每条必须：
- 包含具体数据或量化指标
- 有明确的逻辑推导
- 避免空泛描述

**示例**：
```
❌ 不佳："空调费率超标需要关注"
✅ 规范："空调费率4.78%超预算0.23pp，其中云仓库存较BP增加22.5万套/月，仓租增加985万（0.25%）"
```

### 4.2 数据标注规范

每页涉及数据的，必须标注：
```
【数据标注】
- 来源：具体系统/报表名称（如BI看板-物流费用点位跟踪表）
- 口径：计算公式或统计规则（如物流费用/销售收入）
- 周期：统计时间范围（如2025年1-5月累计）
- 备注：特殊说明（如系统取数逻辑有误）
```

### 4.3 逻辑推导规范

每页必须包含逻辑推导：
```
【逻辑推导】
- 上页承接：承接上一页的核心信息（如"承接P3费用率拆解，本页深入空调超标根因"）
- 本页核心：本页要证明的核心观点（如"本页揭示空调费率超标的根本原因在于云仓库存管理机制与费用管控脱节"）
- 下页预告：为下一页做铺垫（如"下页将展示冰洗品类类似问题的根因分析"）
```

## 五、审计反向约束

### 5.1 生成时必查清单

每页内容生成时，必须同步执行：

| 检查项 | 检查规则 | 不通过处理 |
|--------|---------|-----------|
| 数据自洽性 | 汇总=分量、子集<=全集 | 标记矛盾，追问用户 |
| 一致性 | 同名同值、口径统一 | 标记不一致，追问用户 |
| 完整性 | 无占位符、有基期、无空白 | 标记缺失，追问用户 |
| 可量化性 | SMART+A+T | 补全量化指标 |
| 可追溯性 | 来源透明、公式透明 | 补全数据标注 |
| 可考核性 | 责任到人、可奖惩 | 补全责任人 |
| 术语规范 | 使用标准术语库 | 替换或标记待确认 |
| 逻辑推导 | 无跳跃、有承接 | 补充推导说明 |

### 5.2 禁止事项

- ❌ 生成"描述XXX""X.xx%"等占位符
- ❌ 同一指标在不同页面数值矛盾
- ❌ 目标无基期数据
- ❌ 措施无量化指标
- ❌ 根因分析止于现象层
- ❌ 使用"认知不足""重视不够"等主观归因
- ❌ 系统层归因无具体组织/流程名称

## 七、注意事项

1. **模块丰富度**：每页至少2个模块，总览页和数据页至少3个模块
2. **数据页总结描述**：数据页必须有总结性描述，不能只有表格
3. **根因三层穿透**：根因分析页必须包含现象层→机制层→系统层
4. **逻辑推导完整**：每页必须有上页承接、本页核心、下页预告
5. **审计合规同步**：每页生成时必须同步执行审计合规检查
6. **术语规范**：优先使用TCL内部标准术语
7. **内容密度控制**：每页正文要点3-5条，避免信息过载
