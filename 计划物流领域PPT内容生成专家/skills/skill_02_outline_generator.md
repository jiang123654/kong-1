# Skill 02：大纲生成与逻辑分组

> 所属技能：计划物流领域PPT内容生成专家

## 一、功能定位

Skill 02是PPT生成的**第二阶段**，负责将结构化信息素材库转化为PPT大纲，确定页面结构、逻辑分组和叙事链条。

## 四、逻辑分组方法

### 4.1 六种基础逻辑结构

在对信息逻辑分组时，**最多分为4个方面**。

#### 4.1.1 线性结构
按照时间顺序、空间顺序或逻辑顺序组织内容。
- **适用场景**：项目时间线、发展阶段、执行过程
- **示例**：H1→H2时间线、送装一体推进时间线

#### 4.1.2 因果结构
强调原因和结果之间的关系。
- **适用场景**：问题分析、根因穿透
- **示例**：费用超标原因→结果→影响

#### 4.1.3 比较与对比结构
将两个或多个对象进行对比。
- **适用场景**：H1 vs H2对比、达成vs未达成对比
- **示例**：H1实际3.68% vs H2目标3.42%

#### 4.1.4 问题-解决结构
提出问题，然后提供解决方法。
- **适用场景**：问题分析页、改进措施页
- **示例**：问题（空调超标）→解决（合同降本+云仓调整）

#### 4.1.5 分类结构
按标准分类，每个类别下详细阐述。
- **适用场景**：多品类分析、多区域分析
- **示例**：按品类分类（智屏/空调/冰洗/CIoT）

#### 4.1.6 过程分析结构
描述过程或流程。
- **适用场景**：流程优化、系统建设
- **示例**：PTP项目建设流程

### 4.2 审计反向约束下的分组规则

| 审计检查点 | 反向分组规则 |
|-----------|-------------|
| 目标-路径-资源三角闭环 | 每组信息必须包含：目标→路径→资源 |
| 推导链条完整性 | 禁止逻辑跳跃：现状→问题→根因→措施→目标 |
| 数据自洽性 | 每组数据必须标注口径、来源、计算公式 |
| 可量化性 | 每组目标必须SMART化 |
| 可考核性 | 每组措施必须包含责任人+验收标准+时间节点 |

## 五、叙事链条设计

### 5.1 核心叙事链条

```
现状（H1）→ 问题（超标/延期）→ 根因（三层穿透）→ 措施（合同/系统/运作）→ 目标（H2）→ 资源（呼唤炮火）
```

### 5.2 页面间逻辑推导

每页必须有：
- **上页承接**："承接上一页..."
- **本页核心**："本页要证明..."
- **下页预告**："下一页将..."

**示例**：
```
P3（全品类费用率）→ P4（空调超标根因）
- P3定位超标品类 → P4深入空调根因
- P4揭示机制层问题 → P5展示冰洗类似问题
- P5系统层归因 → P6切换至服务亮点（平衡叙事）
```

### 5.3 叙事平衡原则

- **问题与亮点平衡**：每3页问题后至少1页亮点
- **数据与故事平衡**：数据页后紧跟分析页
- **回顾与前瞻平衡**：H1回顾与H2规划交替

## 六、结论型标题设计

### 6.1 标题提炼方法

#### 6.1.1 六种标题方法

1. **总结法**：从观点/事实/数据中抽取共同点
   - 示例："全品类费用率持平预算，空调冰洗双品类拖累整体"

2. **归纳法**：通过具体实例提出一般性结论
   - 示例："云仓库存与ASP双压是空调费率超标的核心驱动因素"

3. **对比法**：比较不同情况提炼差异
   - 示例："智屏费用率优于预算，空调冰洗大幅超标"

4. **因果法**：分析原因和结果
   - 示例："BC融合推动C单送达率超预期7.5pp"

5. **演绎法**：从一般原理推导具体情况
   - 示例："基于智能补货的物流计划将提升执行效率30%"

6. **类比法**：通过比较提炼结论
   - 示例："就像线路拉直一样，云仓政策调整将直接降低费率0.3pp"

#### 6.1.2 标题约束

- **字数**：<20字
- **内容**：必须包含具体数据或量化指标
- **结构**：揭示因果关系或对比关系

### 6.2 副标题设计

副标题是标题的**补充说明**，一句话解释核心观点。

**示例**：
- 标题："H1费用率3.68%持平预算，H2目标挑战3.42%"
- 副标题："通过BC融合与线路优化，实现降本4850万"

## 九、注意事项

1. **页面数量控制**：标准报告10-20页，极简≤10页，详尽>20页
2. **逻辑分组上限**：每组信息最多4个方面
3. **标题字数限制**：<20字
4. **叙事平衡**：问题与亮点交替，避免连续多页问题
5. **推导链条**：每页必须有上页承接和下页预告
6. **数据页密度**：数据页不超过3个连续，避免信息过载
7. **结论前置**：核心结论页必须在第2页
